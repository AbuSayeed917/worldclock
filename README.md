# Meridian

A live world clock where every city carries its own sky, computed from the real
position of the sun.

**[abusayeed917.github.io/worldclock](https://abusayeed917.github.io/worldclock/)**

## What it does

- **Live clocks** for any of ~120 cities, with an analog dial and a sweeping second hand
- **Real day/night colour** — each card's sky is derived from that city's actual solar
  elevation, so a 3am card sits dark beside a mid-afternoon one
- **A draggable terminator map** showing exactly which half of the planet is in
  daylight. Drag it and every clock on the page travels with you, which is what
  makes it a meeting planner rather than a picture
- **Real sunrise and sunset** per city from the NOAA solar algorithm, including
  polar day and polar night
- **A time converter** — pick a moment in one city, read it in all the others
- **Pinned cities** persisted to `localStorage`

## How it works

### Time

No date library. `Intl.DateTimeFormat` with a `timeZone` option already carries
the full IANA database, including historical and future DST rules, so
[`src/core/time.ts`](src/core/time.ts) is built directly on it.

The one genuinely tricky operation is the inverse — turning a wall-clock reading
in some zone back into a UTC instant. The offset depends on the instant, but the
instant is what you are solving for. `zonedTimeToInstant` guesses, measures the
offset at the guess, corrects, then re-checks. The second pass only matters near
a DST transition, which is exactly where single-pass conversions land an hour out.

### Sun

[`src/core/solar.ts`](src/core/solar.ts) implements the NOAA Solar Calculator:
declination, the equation of time, sunrise/sunset hour angle, and solar
elevation. Everything visual downstream is a function of these numbers.

The day/night boundary is a great circle. Setting elevation to zero and solving
for latitude gives `tan(lat) = -cos(H) / tan(declination)`, which on an
equirectangular map traces a wave whose amplitude is the season and whose
position is the hour. That curve is the terminator strip.

### Colour

[`src/core/sky.ts`](src/core/sky.ts) maps solar elevation to a palette through
keyframes in OKLCH. Interpolating dusk to night in sRGB drags the midpoint
through a muddy grey; OKLCH is perceptually uniform, so the gradient stays
luminous across the whole sweep.

The palette reaches CSS as custom properties registered with `@property` and
`syntax: '<color>'`. That registration is what lets the browser *interpolate*
them — an unregistered custom property is an opaque string, and the sky would
snap between states instead of transitioning.

## Development

```bash
npm install
npm run dev      # http://localhost:5173/worldclock/
npm test         # 47 tests over the time and solar maths
npm run build    # typecheck, then build to dist/
```

### Regenerating assets

Both generated files are committed, so a normal build never needs these:

```bash
# World coastlines -> src/data/worldpath.ts
curl -sL -o /tmp/ne_land.geojson \
  https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_110m_land.geojson
node scripts/build-worldpath.mjs

# Lottie animations -> public/lottie/*.json
node scripts/build-lottie.mjs
```

### Screenshots

`node scripts/screenshot.mjs "Asia/Tokyo" tokyo` renders the site in a given
timezone and reports console errors, failed requests, and what actually rendered.
Passing a timezone is the quickest way to see the palette at a different hour.

## Deployment

Pushing to `main` triggers [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):
tests, typecheck, build, then a Pages deploy via OIDC.

The build step asserts that `dist/index.html` references `/worldclock/assets/`.
The site is served from a subpath, so a wrong Vite `base` produces a build that
works perfectly in local dev and 404s its own CSS and JS once deployed — a
failure worth catching in CI rather than in the browser.
